# 手動の再分類の操作、分類前メモの見せ方、複数行の折りたたみ、メモの編集

- 状態: 承認
- 決定日: 2026-11-12
- 決定者: オーナー

## 背景

[0020](0020-minimal-scope-and-issue-policy.md) で、手動の再分類(長押しメニューの「種類を変更」)をミニマルに入れ、分類前のメモは一覧にだけ出す、複数行は一覧で2行まで表示する、と決めた。その中身の画面を、デザイン見本に描き足した。描くなかで、メモの編集もミニマルに入れることになった。

## 検討した選択肢

- 複数行メモの全文を見せる場所: 詳細画面を作る / 一覧で折りたたみのトグルで展開する
- 編集後の分類: 自動でやり直す / 今の種類のままにして、やり直しはユーザーの手で行う

(オーナーは、折りたたみのトグルと、今の種類のままを選んだ)

## 決定

- 手動の再分類は、長押しメニューの「種類を変更」を押すと、メニューが ToDo / 疑問 / 記録 の一覧に切り替わる形にする。今の種類にチェックが付き、選ぶとメニューが閉じて、そのメモのマーカーだけが変わる。スマホでのドラッグ&ドロップは、0020のとおり別扱い(未決)。
- 分類前のメモは、マーカーの位置に、回転する丸(ぐるぐる)を出す。長押しメニューでは「種類を変更」と「解決にする」を押せなくする。一覧にだけ出す扱いは、0020のまま。
- 複数行のメモは、2行で折りたたみ、右端のトグルで展開と折りたたみを切り替える。0020の「一覧で2行まで表示」を、これで置き換える。
- 折りたたみのないテキスト(1行のメモ、展開中のメモ)をタップすると、編集中になる。キーボードの上に「キャンセル / 完了」を出す。折りたたみ中のメモは、トグルで展開してから編集に入る。
- 編集して完了しても、種類は今のまま。分類のやり直しは、ユーザーの手で行う(種類の手動変更、またはユーザーが起動する再AI分類)。
- 「編集」を、ミニマルの範囲に入れる。0020の「入れる」に追加する。
- 詳細画面は、いまは作らない。

## 議論での論点

(以下はClaudeの提案を含む)

- 詳細画面は、オーナーが「一旦不要」とした。全文は、一覧の折りたたみで見せる。
- 折りたたみ中のテキストをタップしたときの動き(編集に入らず、展開してから編集)と、分類前のメモで「解決にする」も押せなくする点は、Claudeの提案。オーナーが「想像通り」として承認した。
- 分類前を回転する丸で示すのは、オーナーの指示。
- 編集後に自動で分類し直さない、というオーナーの回答は、分類の契約(#3)に影響する。再分類は、ユーザーが起動する操作として分けて考える。
- 手動の再分類とドラッグ&ドロップの扱いは、0020と同じく技術確認のあとに決める。
