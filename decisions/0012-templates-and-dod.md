# Issue・PRのテンプレとDoD、バックログ推移の見せ方

- 状態: 承認
- 決定日: 2026-11-03
- 決定者: オーナー

## 背景

0011で、IssueとPRを使う流れを決めた。テンプレの置き場所、完成の定義(DoD)、バックログの推移をどう見せるかが未決だった。

## 検討した選択肢

- バックログの推移を、Issueとは別にprocessへコピーして残す
- 正本はIssueのままにして、区切りごとに、processへ短いスナップショットだけ残す

## 決定

- IssueテンプレとPRテンプレ、レビューの観点は、`ne0san/postism` に置く。
- Issueテンプレの項目は、背景、困りごと、仮説、受け入れ条件、優先度の理由、関連。
- バックログ推移の正本はIssue。processにはコピーしない。
- 区切りごとに、`retros/` へ数行のスナップショットを残す(選んだIssue、終わったものと落としたものとその理由、Issueへのリンク)。
- ポートフォリオの入口は、0006の2段目(ケーススタディ記事)にする。
- DoDは2層にする。
  - PR単位: Issueの受け入れ条件を満たす / CIが通る / 別セッションのClaudeのレビューへの対応か見送り理由を残す / 仕様が変わるなら同じPRで更新する / 決定が生まれたら決定ログ案を出す
  - 区切り単位: 自分で使ってみた / ふりかえりを書いた(0011の6と7)

## 議論での論点

(以下はClaudeの提案を含む)

- 推移をprocessにコピーすると二重管理になり、食い違いやすい。
- 企業側が見る余裕は小さい想定。ドキュメントが増えるほど、見てほしいものが埋もれる。
- ボードの見た目は現状しか見えない。履歴は、Issueの作成・クローズ日とコメントで追える。
