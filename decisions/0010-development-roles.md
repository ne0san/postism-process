# 開発の分担: コーディングはローカルのClaude Code、進行はClaudeアプリのプロジェクト

- 状態: 承認
- 決定日: 2026-11-02
- 決定者: オーナー

## 背景

コーディングは、オーナーのローカル環境でClaude Codeを使って進めたい。プロジェクト自体の進行は、Claudeアプリのプロジェクトで行いたい。開発プロセスは、実際のプロジェクトに近い形にしたい。

## 決定

次の分担で進める。

| 場所 | 役割 | 実際のプロジェクトでいうと |
| --- | --- | --- |
| オーナー | 優先順位と承認を決める | プロダクトオーナー/PM |
| Claudeアプリのプロジェクト | 整理、調査、計画、デザインの壁打ち、ふりかえり | PMの補佐 |
| ローカルのClaude Code | 実装、テスト、PR | 開発メンバー |
| 過程のリポジトリ(`postism-process`) | 決定、ふりかえり、現在地の正本 | 議事録・意思決定の記録 |
| プロダクトのリポジトリ(`postism`) | コード、仕様、Issues | 開発の正本 |

## 議論での論点

(以下はClaudeの提案を含む)

- プロジェクトの会話で決まったことは、そのままだと会話の中にしか残らない。会話の終わりに「決定ログの案」をもらい、Claude Codeで過程リポジトリに書く。承認するのはオーナーだけ。
- Claude Codeはプロダクトのリポジトリで動く。決定ログは別のリポジトリなので、ローカルで2つを並べて置き、追加ディレクトリとして読ませる案がある(要確認)。プロダクト側のCLAUDE.mdに、現在の結論だけを書いて、決定ログへリンクする方法もある。
- プロジェクトのナレッジはコピーなので、リポジトリと食い違いやすい。薄く保ち、STATUSや決定ログが更新されたら差し替える。
