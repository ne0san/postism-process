# Web版(PC幅)のデザインのルール

- 状態: 承認
- 決定日: 2026-11-17
- 決定者: オーナー

## 背景

[0013](0013-design-principles.md) 以降のデザイン見本は、iOSのネイティブ前提で描いた。[0033](0033-client-expo-mobile-and-web.md) で、クライアントはExpoでスマホとWebを作ると決めた。Web版のために、iOS前提のルールのうち読み替えが要るものと、Webで新しく要るものを、デザイン見本(Web版PC幅、状態)に描いて決めた。

## 決定

- 画面の構成: PC幅は、左のサイドバーと、幅720pxの1カラムの本文にする。サイドバーは「一覧 / ToDo / 疑問 / 記録」、いちばん下に「ゴミ箱」を置く。アイコンは、ToDo・疑問・記録は種類の色、一覧はアクセント色、ゴミ箱はグレーにする。ゴミ箱への入口は、PC幅ではこのサイドバーにする。
- 入力: PC幅のWebでは、入力欄を画面の下の中央に常駐させる([0016](0016-entry-button-popup.md) の「追加ボタン→ポップアップ」を、PC幅のWebに限って置き換える)。1行のうちは端の丸い棒、書き始めると上に伸びて角丸の四角にする。プレースホルダーは「メモ」のまま。送信は Ctrl / ⌘ + Enter、Enter は改行にする。
- 行のメニュー: 長押しの代わりに、行の右端の「…」(ホバーかキーボードフォーカスで出る)と右クリックで開く。中身はiOSの長押しメニューと同じ。
- ガラス表現(半透明とぼかし)は、iOSネイティブだけで使う。Webでは使わず、不透明の面と細い線にする。
- 操作の状態: ホバーは薄い面、キーボードフォーカスはアクセント色の2pxの輪にする。
- ライトとダーク: 全ての画面を、両方描く。
- 文言: 抽象的すぎず、くだけすぎない言い方にする。
- スマホ幅のWeb: いまはデザインしない。実装は後でよい。アプリを使う利点を大きくする方針にする。
- 状態の画面:
  - サインイン: GoogleとAppleのボタンだけ。注記は「Google、またはAppleで続行すると、お客様は Postism の利用規約およびプライバシーポリシーに同意したことになります。」で、2つの語はリンクにする。
  - 読み込み中: 行の形をしたグレーの帯。
  - オフライン: タイトルの下に1行の帯。「オフラインです。オンラインに戻ると、メモの分類と同期が自動で行われます。」
  - 同期エラー: 同じ形の帯。「同期に失敗しました。時間をおいて、再試行してください。」と「再試行」。オンラインなのに送信が失敗した場合(サーバー側の不具合、タイムアウトなど)を想定し、メモは端末に残る。
  - メモが1件もないとき: 「メモはまだありません」と、入力欄の場所を伝える一文。
  - ゴミ箱(PC幅): 行にマウスを乗せると「元に戻す」と「完全に削除」が出る。

## 議論での論点

(以下はClaudeの提案を含む)

- 入力欄の常駐、サイドバーのアイコンの色、サインインとオフラインの文言、ライトとダークの両方を描くこと、文言の方針、スマホ幅のWebを作らないことは、オーナーの指示。
- 画面の構成(サイドバー、幅720px)、行のメニューの入口、Enterと Ctrl / ⌘ + Enter の使い分け(日本語入力の確定と重ならないようにするため)、ホバーとフォーカスの見せ方、各状態の画面の形は、Claudeの提案。オーナーが承認した。
- ガラス表現をWebで使わないのは、オーナーの指示(iOSネイティブの表現のため)。
- 同期エラーの想定場面は、Claudeの想定。0028の同期APIは、送信を1件ずつ成否で返す形のため、バッチの一部だけ失敗したときの見せ方は決めていない。
- スマホ幅のWebについて、Claudeは、アプリへの誘導を前提にしているサービスの例(Spotify、Slack、Google ドキュメント)を挙げた。Webで確認した限りの例で、Slackと Google ドキュメントの情報は古く、いまの挙動は未確認。
