# AI分類コマンドは、まだ分類がないメモにだけ通す

- 状態: 承認
- 決定日: 2026-11-16
- 決定者: オーナー

## 背景

[0028](0028-sync-api.md) で、複数端末の並行操作は、サーバーの処理順の後勝ちにした。ただ、ユーザーの再分類のあとに、AIの分類が遅れて届くことがある。単純な後勝ちだと、ユーザーが直した種類をAIが上書きしてしまう。また、AIの分類は、Streamsの少なくとも1回の配信([0024](0024-event-sourcing-and-infrastructure.md))で二重に動く可能性がある。

## 検討した選択肢

- 単純な後勝ち(処理順で、AIの分類も上書きする)
- AI分類コマンドを、そのメモにまだ分類が1つもないときだけ通す(通さないときは破棄する)
- 人の再分類を優先する規則を、投影側に持たせる

## 決定

- AI分類コマンドは、そのメモにまだ分類(AIによるもの、人によるもののどちらも)が1つもないときだけ通す。分類がすでにあるときは、コマンドを破棄し、イベントは作らない。
- 検証はコマンド側で行う([0026](0026-event-design.md))。ユーザー別連番の条件付き書き込みで、同時に届いても、どちらか一方だけが通る。
- この規則で、AI分類の二重実行も防ぐ。
- 将来の「ユーザーが起動する再AI分類」(STATUSの「あとでやる」)は、この規則の例外として、そのとき別のコマンドとして許可する。
