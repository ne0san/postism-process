# 進め方はスクラム風にする

- 状態: 承認
- 決定日: 2026-11-02
- 決定者: オーナー

## 背景

進め方として、小さく出して使って直す方式と、ウォーターフォール型の2つがあり得る。オーナーは、使って修正し、プロダクトバックログを順次整理していく進め方を希望した。

## 決定

スクラム風に進める。小さく作って出し、自分で使って直し、プロダクトバックログを順次整理する。

## 議論での論点

(以下はClaudeの提案を含む)

- 最大の不確実性は「分類が使えるか」「使い続けるか」で、仕様を先に確定しても分からず、使って初めて分かる。
- 1人なので、儀式(デイリー、役割分担)は要らない。取り入れるのは、バックログ、短い区切り、区切りごとのゴール、自分で使うレビュー、ふりかえり。
- 仕様は、境界(APIと分類の契約)だけ先に厚くして、画面や機能は区切りごとに薄く足す。
- 最初のリリースは、最薄で「投げる → 分類 → 表示」が通り、自分が日常で使える状態。
- 設計の期間にも期限を切る。

## 関連する未決事項

- 区切りの長さ(案は1〜2週)
- 計測する指標(案は、毎日投げたか、分類を直した率、見返した回数)
