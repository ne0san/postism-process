# ミニマル範囲の線引きと、Issue化の方針

- 状態: 承認
- 決定日: 2026-11-09
- 決定者: オーナー

## 背景

デザイン見本([0014](0014-category-marker-colors.md)〜[0018](0018-ai-answer-label.md))が固まり、実装に入る前に、最初に作る範囲(ミニマル)と、バックログをIssueにする基準を決める必要があった。[0011](0011-development-process.md) と [0012](0012-templates-and-dod.md) で、IssueとPRを使う流れとテンプレは決めてある。

## 検討した選択肢

- ミニマルの完成ラインを「毎日メモを投げて、種類別に見返せる」にする
- ミニマルの完成ラインを「投げる、種類別に見返せる、ToDoと疑問をその後の自分の処理で使える」にする

(オーナーは、後者を選んだ)

## 決定

### ミニマルの完成ライン

自分がメモを投げる。種類別に見返せる。ToDoと疑問を、その後の自分の処理で使える。

### ミニマルの範囲

- 入れる: 投げる(入力) / 裏で分類 / 一覧と種類別タブ / 複数行は一覧で2行まで表示 / 解決にする / 手動の再分類
- 外す: 並び替え、解決済みの表示切替、AIによる回答、PC版とApple Watch版、長押しメニューの細部

### ミニマルでの暫定の扱い

- 手動の再分類は、長押しメニューの「種類を変更」だけにする。スマホでのドラッグ&ドロップは、技術確認のあとに回す(未決のまま)。
- 解決済みは、常に表示する。ToDoは打ち消し線とチェック入りのマーカー。疑問は、暫定で打ち消し線にする(解決済みの疑問の見せ方は、別の会話で決める)。
- 分類が終わる前のメモは、一覧にだけ出して、種類別のタブには出さない。

### Issue化の方針

- Issueは、次に着手する可能性がある範囲だけ作る。ミニマルの範囲は、今からIssueにする。ミニマルを作ったあとは、次に着手する可能性がある範囲だけをIssueにする。
- それ以外は、STATUS.md の「あとでやる」に1行ずつ置く。
- 「あとでやる」の項目をIssueにしたら、その行を「あとでやる」から消す。リンクはIssue側に残す。
- 区切りの初めと終わりに、「あとでやる」とopenなIssueを突き合わせる。作業の分担と指示の置き場所は、CLAUDE.md に書く。

## 議論での論点

(以下はClaudeの提案を含む)

- 「ToDoと疑問を、その後の自分の処理で使える」という完成ラインは、オーナーの発言。これを満たすため、当初の案で外していた「解決にする」と「手動の再分類」をミニマルに入れた。
- 手動の再分類を長押しメニューだけにする案、解決済みを常に表示して疑問は暫定で打ち消し線にする案、分類前のメモの見せ方の案は、Claudeの提案。オーナーが承認した。
- Issue化の基準(「ミニマルを作成後、次に着手する可能性がある範囲だけ」「Issueにしたら『あとでやる』から消す」)は、オーナーの提案。
- 「あとでやる」をSTATUS.mdに置く案と、作業の分担(Issue案の作成と確認はプロジェクト、Issueの作成は、オーナーの承認のあと)は、Claudeの提案。
- 分類の契約と精度確認、AIプロバイダー、分類を動かすタイミング、フレームワークと実行基盤が決まらないと、着手できないIssueがある。
