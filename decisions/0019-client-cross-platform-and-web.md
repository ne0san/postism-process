# クライアントは、クロスプラットフォームのアプリとWebを前提にする(0003を置き換え)

- 状態: 承認
- 決定日: 2026-11-09
- 決定者: オーナー

## 背景

[0003](0003-pwa-first.md) で「クライアントはPWAを先行する」と決めた。しかし、オーナーはPWAを、WebとネイティブのUIを1つのコードで両立できる仕組み(React NativeとReact Native Webの組み合わせのようなもの)だと勘違いしていた。この前提が違っていたため、0003の決定を取り下げる。

## 検討した選択肢

(オーナーの指示は、前提を「クロスプラットフォームアプリとWeb」にすることのみ。他の選択肢は検討していない)

## 決定

- 0003の「PWA先行」は取り下げる。
- クライアントは、クロスプラットフォームのアプリとWebの両方を前提にする。
- 具体的なフレームワークは、後で選ぶ。

## 議論での論点

(以下はClaudeの提案を含む)

- 0003の「ブラウザ向けに作れば、iOSでもAndroidでも同じ画面でまず動く」という理由は、PWAの前提が変わったので、そのままでは使わない。
- [0016](0016-entry-button-popup.md)、[0017](0017-screen-structure-and-labels.md) の見本は、iOSのネイティブ前提で描いてある。今回の前提とは食い違わない。両方にある「PWAで実現できるか」の確認は、フレームワークを選ぶ際の確認項目に読み替える。
- [0004](0004-backend-typescript-effect.md) にある「PWAと同じ言語になり、スキーマを共有しやすい」という理由は、クライアントのフレームワークの選定結果によって変わる。
